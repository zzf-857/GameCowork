This is GameCowork's own Editor-only Unity UPM package. It contains no original Codely bridge, account client, remote registry dependency, or embedded native streaming library. Unity 2022.3 is the first compilation target; Tuanjie and other versions require separate editor tests.

Every own capture mode now requires input identity from a successfully decoded actual frame: `X-GameCowork-Capture-Epoch` (32-hex per-capture ID), `X-GameCowork-Geometry-Revision` (positive integer) and `X-GameCowork-Instance-Id` (signed EditorWindow ID). Send these as `captureEpoch`, `geometryRevision` and `instanceId` on `/input`. Replacement/restart changes the epoch; ordinary frames preserve geometry revision, while source/output fit, actual GUIView identity/screen geometry, DPI or content mapping changes increment it. The main-thread handler rejects missing identities, an old epoch/revision or another window before injecting input; old clients must refresh. Failed capture does not publish new geometry and cannot accept input. Revision changes cancel only the original capture's held interactions; mouse release is outside the original window's content so a resize does not commit a pending button. `EditorWindow.position.x/y` can switch between GUI-local and screen coordinates around `GrabPixels`; complete-GUI identity uses the authoritative `GUIView.screenPosition` and derived logical content offset instead of those context-dependent raw values. Explicit all-stop and shutdown also reclaim zero-holder bridge-owned windows retained after lease expiry, while preexisting or still-held windows remain open.

Complete-GUI capture currently transports bounded JPEGs from real visible/occluded own Editor windows. It does not provide the original native hidden-window lifecycle, WebRTC/audio, dock-tab dragging, popup/object-selector composition, external drag/drop or native IME parity. Those capabilities remain explicit unsupported metadata. No original native DLL is loaded or redistributed. Install the local package only in an explicitly selected project, with a dependency such as `"cn.gamecowork.bridge": "file:F:/AI/AgentMake/CyberSoftwares/GameCowork/src/editor-bridge"`. Opening that project starts a loopback TCP listener and atomically publishes `Temp/.com-unity-gamecowork.json`. `project_path` is the project's Assets directory because the current CLI takes its parent when verifying the handshake. Shutdown/domain reload closes this package's listeners and removes only its own unchanged connection file.

The server sends `WELCOME UNITY-TCP FRAMING=1 SERVER_VERSION=2 PROJECT_ROOT=<URL-encoded absolute root>\n`. Subsequent frames use an unsigned 8-byte big-endian byte length and UTF-8 payload. `CLIENT_VERSION=2` and `PLATFORM=cli` are accepted. `ping` responds with `{success:true,message:"pong"}`. Requests are `{type:"manage_window_bridge",params:{action,port?},request_id}`; replies preserve `request_id` and return `result:{success,data? ,error?}`. Supported actions are `list_windows`, `start_stream_server`, `stop_stream_server`, and `get_stream_server_status`. Other tools return explicit unsupported errors.

Read-only TCP tools additionally support `type:"manage_editor"` with actions `get_state`, `get_project_root` and `get_selection`. They use actual EditorApplication, Application, Selection and AssetDatabase data on the main thread. State includes isPlaying/isPaused/playMode/isCompiling/isUpdating/unityVersion/projectRoot/pid and actual Console error/warning counts when that Editor's API is available; selection includes actual object instance IDs, names/types, activeAsset and assetPaths. The application's native adapter returns the existing Core-shaped `{status:"success",response:{success:true,data}}` without starting a model. `_internal_asset_listening/status` returns supported:false/listening:false/isListening:false because this local bridge has no implemented/configured generation listener. Unrecognized actions and scene/object write tools remain explicit errors.

`manage_editor` also accepts `play`, `pause`, `resume`, `stop` and `refresh`; resume uses `singleFrame:true` for one actual runtime frame while staying paused, or `false` for continuous play. `timeoutSeconds` is bounded to 1..180 (default 60). Acceptance returns actual state with `pending:true`, `operationId`, controlAction/controlStatus/controlPhase, never an invented completed result. `EditorControl` runs on EditorApplication.update, persists that operation in the Editor's own SessionState, and resumes across Play/Stop/compilation assembly reloads. The native adapter polls only that verified project and operation until the actual requested state is complete; transient own-bridge reload disconnects are retried, a changed identity or false completion is rejected. Refresh first stops Play Mode, clears the actual Console, imports changed assets, and waits for compilation/updating to settle in Edit Mode; refresh completion can legitimately return hasErrors=true when the actual Console has errors. Unknown or timed-out results do not automatically start play. Closing a preview or losing an Editor is not permission to substitute another project.

The product control waiters carry requestId/action in addition to fixed workspace root/key and cancellation generation. Passive get_state or late unrelated control responses cannot satisfy a refresh waiter or clear another pending operation. The Play button keeps the observed state until real refresh/play completion; the pause button toggles pause/continuous resume. `node tests/contracts/frontend-editor-control.test.mjs` exercises both maintained generations' actual extracted waiters/Play handlers. `node tests/e2e/editor-control-e2e.mjs` uses an own isolated runtime-frame observer, the real Rust host/Core and actual GUI controls; `--http-only` verifies only the native control APIs, `--editor <installed exe>` selects a separately verified engine/native scene, `--agent <guarded own exe>` selects the fixture Agent resources without starting a model, and `--packaged` selects app EXE/Core/frontend/bridge and checks normal/guarded source/executable identities. A source-only controls pass does not prove the assembled app contains these changes.

Stage 6 adds actual Agent control completion and scoped cancellation. The TCP welcome now advertises `EDITOR_CONTROL_CANCEL=1` and an `EDITOR_DOMAIN` identifier. Before submitting a control, the own CLI freezes its canonical project root and generates a process client nonce plus a fresh per-request secret. `gamecowork_control:{clientId,cancelToken,projectRoot,domainId}` travels outside model tool arguments; it is not included in state replies, diagnostics, capability URLs or project files. Cancellation/status uses a separate verified loopback TCP connection because the original connection can be waiting for main-thread work. `_gamecowork_cancel_editor_control` and `_gamecowork_editor_control_status` accept params containing that same identity plus the original `requestId` and optional `operationId`. Unknown/mismatched identities never cancel another caller. Request IDs alone, including `ntb-N`, are not an authorization credential.

`EditorCancellation` parses bounded strict JSON using BCL only on network threads and tracks at most 256 request/client identities per Editor domain. Its admission, cancellation and effect-start locks prevent a confirmed pre-effect cancellation from later reaching Unity APIs. A same-domain pre-cancel tombstone rejects a late original request; retired or out-of-order request IDs cannot be readmitted after cleanup. Original TCP owners are tracked separately: an ended last owner cancels an unapplied request, while a reloaded accepted request must obtain authenticated ownership renewal on its new primary connection before applying an effect. Freeze precedes the main-thread SessionState save at shutdown/reload, so a cancellation confirmed before reload remains cancelled afterwards. Invalid saved root/nonce identity is discarded. All Unity APIs and SessionState access remain on the Editor main thread.

The CLI polls only get_state after acceptance and returns a successful tool result only for the same root, operation ID, completed status and requested actual play mode. Reload reconnects never resend the original play/refresh/stop. A bounded 1..180-second budget and caller AbortSignal cover polling/reconnection. Cancellation of queued/unapplied work can report cancelled:true/applied:false; an effect already submitted/applied reports applied:true and is never automatically stopped or rolled back. An unknown outcome stays unknown. The local-mode Wiki remains offered with an explicit unsupported explanation when no local source exists, and does not automatically prefetch a remote catalog.

Starting the preview HTTP listener returns `data:{status:"success",running:true,signalingUrl,transport:"image-frames",projectRoot,pid,capturing,error}`. The URL includes a random 192-bit capability path `/api/tauri/window-bridge/local/<token>` retained by the existing frontend URL sanitizer. The listener binds only 127.0.0.1, requires the capability path, rejects foreign browser Origins, and uses bounded local sockets/queues. It needs no administrator HTTP URL reservation. Do not log or expose the capability URL outside the local session.

Relative routes beneath that URL are:

| Method and route | Request and result |
| --- | --- |
| GET `/health` | Actual running server `{status:"ok",transport:"image-frames",projectRoot,pid}` |
| GET `/windows` | Existing editor windows `[{title,typeName,instanceId,captureSupported}]` |
| GET `/stream/status` | Actual server/capture status; no connection success inferred from this alone |
| POST `/stream/start-offscreen` | `{streamId?,instanceId?,windowType,captureMode?,width,height,dpr,fps}` creates/replaces only that real capture; omitted streamId means `default`; `editor-window` uses the full GUIView |
| POST `/stream/resize` | `{streamId?,width,height,dpr}` scales only that output; `{compositeId,width,height,dpr}` updates a compound receiver's slot outputs without changing editor window layout |
| GET `/frame?streamId=<id>` | Actual JPEG with stream/sequence/output-size headers; Source-Width/Height and Content-Rect `[x,y,w,h]` describe the real source and aspect-fit content. Omitted id means `default`, HTTP 409 if inactive/not ready |
| POST `/input` | Existing pointer/key JSON plus `streamId?` translated to the selected actual EditorWindow instance on its main thread |
| POST `/stream/start-composite` or `/stream/update-composite` | `{compositeId?,width,height,dpr,fps,focusedSlotId,slots:[{slotId,windowType,instanceId?,title,rect:{x,y,w,h}}]}`; returns supported real stream IDs and explicit unsupported-slot reasons |
| POST `/stream/stop` | `{streamId}` releases only that stream, `{compositeId}` only that compound receiver, an empty body stops all; TCP `stop_stream_server` remains the explicit server-wide stop |

This transport captures SceneView/GameView rendered content, not arbitrary desktop pixels or complete Inspector/Hierarchy UI. Up to six captures run concurrently, each with an independent latest immutable frame, size, sequence, input target and consumer lease. A selected `instanceId` must belong to a real supported window of this editor. Compound layouts accept up to 16 bounded normalized slots; Scene/Game slots use actual streams while unsupported window slots remain explicit text placeholders. Overlapping tab groups display the focused slot while their supported streams remain independently decoded. Different compound receivers use a unique compositeId namespace. No placeholder image claims that Inspector, Hierarchy, Console or Project capture is implemented.

It scales real render textures, reads pixels and encodes JPEG at 1..30 requested fps, with 16..1920×16..1080 limits per output and a 2 MiB frame limit. Unity compilation/updating pauses capture; no old picture is claimed to be a new frame. Missing textures, unsupported views/inputs, queue saturation and editor failures are explicit errors. `windowBridge.html` uses its own `assets/gamecowork-image-frames.js` to verify stream identity, sequence, decoded dimensions and actual JPEG bytes before reporting streaming. Its compound branch decodes real sources independently and composes them with accurate unsupported-slot labels. Stop/switch discard late replies; input and pointer coalescing retain the selected stream identity. The original WebRTC branch remains for other backends. WebRTC/audio/full editor window parity is not complete.

SceneView reuses its camera render texture for transparent handles after drawing the 3D scene. The bridge copies it in the actual camera post-render callback (or SRP end-camera callback) before that clear, then reads the private copy on update. It unsubscribes on stop and publishes a new SceneView frame sequence only after a real render callback. GameView reads the actual editor's `m_RenderTexture`; unsupported field layouts fail explicitly. Neither capture path reads other applications or the desktop.

A monotonic 15-second frame-poll lease stops encoding and releases only that stream's readback resources when its receiver disappears. Polling a different stream or health/status does not renew it. Expiry keeps editor windows open and leaves the local control listener available. Window references are shared: stopping one capture cannot close the selected window while another capture holds it; explicit stop closes only a bridge-created window at the last holder. Keys/buttons injected through a capture are released on its stop. A closed application cannot leave unattended captures encoding indefinitely.

All network requests that touch Unity objects are queued to the editor main thread; TCP requests are bounded to 1 MiB, HTTP headers to 16 KiB and bodies to 64 KiB. Each listener admits at most 16 clients, with a shared 64-request main-thread queue and finite waits. Browser input is scoped to the selected view of the editor owning the handshake root. Multi-project dispatch must keep one connection per project instead of changing the current CLI singleton's mutable project root while a socket remains connected.
