# GameCowork Editor Bridge

This is GameCowork's own Editor-only Unity UPM package. It contains no original Codely bridge, account client, remote registry dependency, or embedded native streaming library. Unity 2022.3 is the first compilation target; Tuanjie and other versions require separate editor tests.

Current editor context reads (2026-10-02) use `manage_editor` through `EditorContextQueries.cs` on the Editor main thread. The six actions are `get_selection`, `get_project_root`, `get_windows`, `get_tags`, `get_layers` and `get_active_tool`. Selection/root retain the established real-data schema. Windows enumerate actual open `EditorWindow` instances with signed IDs, title, concrete type, focus and finite geometry; layers return only named native slots 0..31. The active tool includes actual enum/custom type availability, pivot settings and handle vectors. Limits are 256 windows, 1,024 tags, 4,096 characters per name and 900,000 response bytes; exceeding these fails rather than inventing incomplete rows. Reads do not select, focus, create windows, switch tools or alter tags/layers/Prefs. `get_state` remains a separate established state read; setting tools, focus, tags or layers is unsupported.

Current asset/package reads use `EditorAssetQueries.cs` and `EditorPackageQueries.cs`; the own Agent registers `unity_asset` and `unity_package`, and Rust admits only their implemented read actions. Asset queries use real `AssetDatabase` metadata and backing paths under `Assets` or a currently registered package's `assetPath` / `resolvedPath`. Safe bare-relative paths retain the original `Assets/` compatibility; absolute paths, traversal, unregistered package paths, junction/symlink roots or descendants, and disagreement between the physical path and AssetDatabase fail. Queries do not refresh/import assets, change selection/dirty state/Prefs, write manifest or package lock files, or issue network UPM list/install/remove requests.

Uses actual `FindAssets`, sorts scanned matching paths, and returns `data.assets` plus native/scanned/returned counts, `totalAssetsExact`, warnings and completeness. |

| `manage_package/list_packages` | Optional integer `timeoutSeconds` 1..300. Asset scans stop at 4,096 native matches or 2.5 seconds. Scan/path/detail limitations retain `queryComplete`, `truncated`, `scanTruncated`, `totalAssetsExact` and `filterLimitation`; an approximate count is never labeled exact. Package output is limited to 1,024 rows, 128 dependencies per package and bounded text (description 4,096 characters); clipping or an Editor currently compiling/updating makes the snapshot incomplete. Both handlers cap UTF-8 responses at 900,000 bytes. Asset mutations and package install/remove remain unimplemented; the read foundation does not complete those later write lifecycles.

`generatePreview:true` requests actual native `AssetPreview` pixels. `previewStatus` distinguishes `pending`, `unavailable`, `unsupported`, `unsupported-no-graphics`, `budget-exhausted`, `too-large`, `failed` and `ready`; the default is `not-requested`. Only `ready` has `previewReady:true`, Base64 PNG and actual dimensions. Native generation can complete after this query; a later explicit query may observe readiness. There is no fake image or mini-thumbnail fallback. Encoding limits the longest dimension to 256, each PNG to 128 KiB, aggregate PNG bytes to 384 KiB and native preview requests to four per response. An explicitly requested unavailable preview leaves metadata available but `queryComplete:false`; outer metadata success is not image success. Temporary render/readback objects are released and the prior active render target is restored.

Current scene writes use `EditorSceneMutations.cs` only through approved Agent actions. `manage_gameobject/create` creates an empty object with bounded `name`, optional exact loaded `parent`, local `position` / Euler `rotation` / `scale`, and `setActive`; without a parent it uses the active ordinary scene. `modify` requires an exact loaded `target` and at least one of those transform/active fields. Vectors require three finite numbers in -1000000..1000000. Both use actual Unity Undo, preserve prefab-instance modifications, mark changed scenes dirty and return actual target/scene IDs, `changed`, `dirty` and `undoSupported:true`; they do not add arbitrary components, instantiate prefab assets or save files. Loaded ordinary unsaved scenes can be edited in memory. Play Mode, compilation/updating, prefab assets and preview/Prefab Stage targets are rejected.

`manage_scene/save` saves only an already loaded ordinary scene to its existing Assets-relative `.unity` or `.scene` file; optional `path` / `sceneHandle` must identify the same single loaded scene, otherwise it uses the active scene. It never opens a scene or performs SaveAs. Save verifies the original project/Assets generation and loaded scene file's Windows volume/file identity, rejects reparse/hardlink/read-only/replaced storage and returns actual `saved`, `changed`, clean `dirty:false` and `undoSupported:false`. Save is not rolled back by Undo or later cancellation. Identity/path checks are repeated close to the effect, but Unity's path-based save still has a last-check-to-use TOCTOU window; this is not an atomic filesystem transaction.

Scene writes require transport-level `gamecowork_control` with the registered original project, Editor domain, process client and per-request cancel nonce, plus original TCP ownership. The model cannot supply that identity. A confirmed cancellation before effect admission prevents mutation; after submission the response distinguishes applied effects from confirmed zero-effect cancellation and unknown outcomes. The Agent freezes the originating scene root before approval, checks the actual applied operation/target/save result, and does not resubmit immediate effects after reload or unconfirmed completion. Permission classification uses the executed `action`; conflicting `command` / `operation` selector aliases cannot make a write a read. The CLI scheduler executes scene writes, Editor controls and Console clear individually in submitted order; read batches stop at the next mutator, so modify completes before a following save. The generic Rust local-tool adapter rejects scene writes rather than bypassing approval.

The source `editor-scene-mutations-smoke.mjs` driver verifies actual Undo and file bytes, nonce cancellation, static path/file-generation refusal and real domain reload. The separate `editor-scene-mutations-agent-smoke.mjs --package <same-source guarded CLI directory>` verifies model-issued IDs, approval/rejection, queued/applied cancellation messages, no resubmission and same-turn modify-to-save ordering with a loopback simulated Provider.
