# 星辰 AI 视频 API 接入文档

版本 1.3 · 2026-10-02

本文面向星辰 AI 用户，介绍当前视频模型、最终售价、请求参数、参考素材、任务恢复与原片下载。示例统一使用星辰 AI 地址和本站模型 ID，无需上游账号。

> **两种使用方式：** 通过 API 接入时，使用绑定「视频大杂烩」分组的星辰 AI API Key；通过画布视频入口时，登录星辰 AI 账户，无需手动填写 Key。两者目录与功能分开更新，不要把画布已接入理解为公开 API 已全部开放，也不要把 API 新增模型理解为画布已经同步。

> **当前边界：** 视频大杂烩 API 目录与价格已配置下列 8 款。画布目前仍是旧目录，新增五款全参 / WAN 尚未接入画布。目录和价格核验不等于每款模型都完成了真实生成验收；实际可用性仍受权限、参数、内容审核和服务状态影响。

## 2. 统一地址与认证

Base URL：`https://xcai.pro`。所有 API 请求使用绑定 **视频大杂烩** 分组的星辰 AI API Key：

```http
Authorization: Bearer YOUR_XCAI_API_KEY
```

本文路径已经包含 `/v1`。软件如要求版本化地址，可填 `https://xcai.pro/v1`，不要拼成 `/v1/v1/videos`。不要使用上游密钥，也不要将密钥放入 URL、公开代码或截图。

以下为 Bash 配置示例：

```bash
export XCAI_API_BASE='https://xcai.pro'
read -r -s -p '请输入星辰 AI API Key: ' XCAI_API_KEY
printf '\n'
export XCAI_API_KEY
```

查询当前 Key 的模型目录：

```bash
curl --fail-with-body "$XCAI_API_BASE/v1/models" \
  -H "Authorization: Bearer $XCAI_API_KEY"
```

请求的 `model` 使用第 1 节的 **API 模型 ID**。中文名称便于识别，不要自行替换为其他平台的别名。模型可见不代表任意参数或素材都能通过生成。

## 3. 请求参数与素材格式

不同模型使用不同字段。尤其注意：**普通特价的 `images` 是原图 Base64 / Data URL，不是图片网址。**

| 模型 | 成片时长 | 画面比例 | 素材字段 |
| --- | --- | --- | --- |
| `3.0`、`3.5` | `duration` | `ratio` | `images`：原图 Base64 / Data URL |
| H3-KS | `seconds` | `aspect_ratio` | `references`：公开媒体地址 |
| 全参 2.0、全参 2.5、全参 2.5 非官 | `seconds` | `aspect_ratio` | `references`：公开 HTTPS 媒体地址 |
| 两款 WAN | `seconds` | `aspect_ratio` | `references`：公开 HTTPS 媒体地址 |

共同字段为 `model`、`prompt`、`resolution`。每次请求生成一条，不要使用 `n>1`。本文不承诺 `seed`、`fps`、`callback_url` 是所有模型的通用能力。

### 参考素材数量

上限依次为图片 / 视频 / 音频，不代表必须全部提供。

| 模型 | 图片 / 视频 / 音频 | 额外限制 |
| --- | --- | --- |
| 特价 2.0 | 9 / 0 / 0 | 不接受音视频参考 |
| 特价 2.5 | 30 / 0 / 0 | 不接受音视频参考 |
| H3-KS | 6 / 0 / 2 | 不接受视频或首尾帧模式 |
| 全参 2.0 | 9 / 3 / 3 | 合计不超过 12 份；参考音视频每个 2–15 秒 |
| 全参 2.5 | 30 / 10 / 10 | 合计不超过 50 份；参考音视频每个 2–30 秒 |
| 全参 2.5 非官 | 30 / 10 / 10 | 每份素材不超过 25MB |
| WAN 可参考视频 | 1 / 1 / 1 | 当前已核验子集 |
| WAN 不可参考视频 | 1 / 0 / 1 | 不接受参考视频；当前已核验子集 |

### 画面比例

- 普通特价、新全参及两款 WAN：`16:9`、`9:16`、`1:1`、`4:3`、`3:4`、`21:9`。
- H3-KS：`16:9` 或 `9:16`。
- 不要使用表外分辨率或时长，也不要从模型名称推测支持 4K、首尾帧等能力。

### `references` 示例

```json
[
  {"type": "image", "role": "reference", "source": "https://YOUR_MEDIA_HOST/image.png"},
  {"type": "video", "role": "reference", "source": "https://YOUR_MEDIA_HOST/video.mp4", "duration_seconds": 3},
  {"type": "audio", "role": "reference", "source": "https://YOUR_MEDIA_HOST/audio.mp3", "duration_seconds": 3}
]
```

这里只演示字段，不适用于禁止音视频参考的模型。替换为自己有权使用的真实文件地址；音视频填写文件的**真实时长**，不能为了过校验伪造。图片、视频、音频各自按添加顺序编号，提示词中的 `@图片1` 等引用必须有对应素材。

## 4. 普通特价 2.0 / 2.5

- `3.0`：720p，5 / 10 / 15 秒，¥3.50 / 条。
- `3.5`：720p，30 秒，¥3.50 / 条。
- 支持无图片的文字请求；提供图片时使用 PNG / JPEG / WebP 原始字节的 Base64 或 Data URL，保持顺序。
- 两款都不接受参考视频或音频，不使用旧 native 的 `video_b64s`、`audio_b64s` 字段。

可选 `face_direct` 是 JSON 布尔值，默认 `false`。设为 `true` 时必须至少提供一张图片；不改变表价，也不开放音视频参考。这个参数不保证审核通过，不是更换模型或绕过内容限制的开关。

内联素材规格为单文件最多 50MiB、图片合计最多 70MiB、JSON 请求体最多 128MiB；Base64 会增加体积，实际请求还受本站网关限制。不要把网址或本地路径填入 `images`。

## 5. 新全参 2.0 / 2.5

这两款按秒计费，与旧 `3.0-native`、`3.5-native` 不同，不要混用 ID 或素材字段。

| 选项 | 全参 2.0 | 全参 2.5 |
| --- | --- | --- |
| ID | `sd-native-full-2.0` | `sd-native-full-2.5` |
| 成片秒数 | 4–15，整数 | 4–30，整数 |
| 分辨率 | 480p / 720p / 1080p | 480p / 720p |
| 提示词 | 最多 4000 个 Unicode 字符 | 最多 4000 个 Unicode 字符 |
| 参考音视频 | 每个 2–15 秒 | 每个 2–30 秒 |

图片每张不超过 30MiB，公开外链音视频每个不超过 100MiB；这是模型素材规格，不表示星辰网页已经开放同等容量的上传功能。本站界面限制与网关限制仍须同时满足。

保留提示词、素材顺序和真实媒体时长。不要自动添加用户未填写的引用，也不要把按秒单价当作整条售价。

## 6. 全参 2.5 非官与 WAN

### 全参 2.5 非官

`sd-native-full-2.5-nonofficial` **按条收费**：480p 为 ¥9.50 / 条，720p 为 ¥13.50 / 条。

- 720p：整数 5–30 秒。
- 480p：整数 5–30 秒中**不包含 12、15 秒**；不要把它当作完整连续区间。
- 每份素材不超过 25MB；最多 30 图 / 10 视频 / 10 音频。
- 使用 `seconds`、`aspect_ratio`、`references`，不是旧 native 内联格式。

### 两款 WAN

`wan-3.0-video-ref` 与 `wan-3.0-no-video-ref` 当前已核验规格均为 **720p、4 秒、¥0.50 / 秒**，倍率 1 时每条 ¥2.00。

区别在于是否允许视频参考：可视频版最多 1 图 / 1 视频 / 1 音频；不可视频版最多 1 图 / 1 音频。当前文档不扩大承诺其他时长、素材数量或分辨率。

## 7. H3-KS

在星辰 API 中使用 `minimax-h3-1080p`，显示名称为 H3-KS。

- 档位 1080p，整数 5–15 秒，横屏 `16:9` 或竖屏 `9:16`。
- 固定 **¥5.10 / 条**，不乘秒数，再乘账户适用倍率。
- 支持文字请求，最多 6 张图片 / 2 段音频，不支持视频参考。
- 图片每张最多 5MiB，合计最多 20MiB；素材通过 `references` 传递，建议使用公开 HTTPS 文件地址，`role` 为 `reference`。
- 不支持首尾帧模式、768p 或 2K，不要套用已暂停的旧 H3 参数。

成片需检查实际像素与时长，不能仅依据请求中的档位交付。

## 8. 接口总览

以下路径均相对于 `https://xcai.pro`，使用 Bearer API Key。实际开放范围以账户权限和本站服务状态为准。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/v1/models` | 当前 Key 可见的模型 |
| POST | `/v1/videos` | 创建一条视频任务 |
| GET | `/v1/videos/{task_id}` | 查询原任务状态 |
| GET | `/v1/videos/{task_id}/content?download=1` | 鉴权下载原片 |

本文不将上游的全部接口视为本站已开放接口。尤其不要直接照搬其他站点的媒体分片上传、回执查询或下载别名路径。

## 9. 参考素材准备

1. 确认素材是可解码的图片、视频或音频，且有权用于本次生成。
2. 普通特价：对原始图片字节做 Base64 编码，不压缩成缩略图，不填写网址。
3. H3 / 新全参 / WAN：准备无需交互登录即可读取的媒体文件直链，不是网页分享页、本机路径或内网地址。
4. 检查素材类型、数量、文件大小、实际时长及提示词引用。
5. 私人素材的临时链接须覆盖任务处理时间；避免公开敏感素材，不在客服截图中暴露签名链接。

**本站媒体分片上传接口未在本文承诺开放。** API 用户请先准备自己的可访问媒体地址；画布内置上传仅代表该页面已支持的能力，不能据此推断公开上传 API 已开放。

## 10. 提交回执与防重复

每个希望生成的视频使用独立本地目录。选择第 15 节的一个示例保存为 `request.json`，核对参数和预计金额。

在该操作目录保存唯一编号：

```bash
umask 077
test -s operation.id || python3 -c 'import uuid; print(uuid.uuid4())' > operation.id
```

**确认要付费生成后，只提交一次：**

```bash
curl --fail-with-body --retry 0 \
  "$XCAI_API_BASE/v1/videos" \
  -H "Authorization: Bearer $XCAI_API_KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(cat operation.id)" \
  --data-binary @request.json \
  --dump-header submit.headers \
  --output submit.json
```

成功回执应包含非空 `id` 或 `task_id`。保存任务 ID、原始请求文件和操作编号；`queued` 或 HTTP 202 只表示受理，不等于生成完成。

| 提交结果 | 处理方式 |
| --- | --- |
| 成功且有任务 ID | 保存 ID，转入 GET 查询 |
| 409，原操作仍在处理 | 保留原 Key、原 UUID、原请求，按提示核查 |
| 409，请求冲突 | 检查相同 UUID 的请求内容是否发生变化 |
| 超时、断网、5xx、成功但无任务 ID | 标记结果不确定，保留记录，联系站内客服核查是否受理 |
| 明确参数错误或任务失败 | 先处理原因；确认要生成新视频时才新建操作 |

不要无限循环 POST，不要换 Key / UUID 来“重试”。同一操作的请求字节、字段和素材顺序必须保留；**客户端没收到回执，不代表服务端没接到任务**。本文不承诺通过重新 POST 找回未知任务。

## 11. 查询任务与恢复

```bash
export TASK_ID='替换为已保存的任务编号'
curl --fail-with-body "$XCAI_API_BASE/v1/videos/$TASK_ID" \
  -H "Authorization: Bearer $XCAI_API_KEY"
```

| 状态 | 含义 | 客户端动作 |
| --- | --- | --- |
| `queued` | 等待处理 | 稍后查询原任务 |
| `in_progress` | 正在生成或后台处理 | 继续 GET 原任务 |
| `completed` | 服务报告完成 | 下载并校验文件 |
| `failed` | 服务报告失败 | 保存错误，核对账务与失败处理 |

已有客户端可沿用 5 秒查询间隔；遇到 429 时遵守 `Retry-After`，不要并发密集查询。进度值可能缺省，不按等待时间编造进度。

浏览器关闭、软件退出或查询暂停不表示任务被取消。恢复时读取原任务 ID 继续 GET。未知状态、登录过期、网络异常与上游明确失败应分开处理；不因前端等待结束而重新付费生成。

## 12. 原片下载与校验

完成后从本站鉴权接口下载，先保留为临时文件：

```bash
curl --fail-with-body --retry 0 \
  "$XCAI_API_BASE/v1/videos/$TASK_ID/content?download=1" \
  -H "Authorization: Bearer $XCAI_API_KEY" \
  --dump-header download.headers \
  --output result.mp4.part
```

确认 HTTP 状态正确、内容不是 HTML / JSON 错误、文件能解码播放，并检查真实时长和分辨率，再改名为 `result.mp4`。有 `Content-Length` 或校验值时同时核对。

**下载失败只恢复下载，不重新生成。** 若接口支持断点读取，只有 HTTP 206 且 `Content-Range` 起点正确才追加；返回 200 时从头保存，不能把完整文件追加到旧文件末尾。

普通网页链接或 `<video src>` 不会自动附带 Bearer Key。使用受控鉴权下载或可信后端代理，不把 Key 放入 URL，也不要向未知重定向域名转发认证头。

## 13. 常见错误与处理

| 错误或现象 | 处理方式 |
| --- | --- |
| 401 | 检查 Key、Bearer 格式、有效期；画布用户重新登录 |
| 403 | 检查账户、模型权限和访问限制 |
| 404 / 不支持的视频模型 | 检查 API ID、分组、当前开放目录及路径 |
| 400 / 422 | 检查秒数、分辨率、素材格式和必填参数 |
| 非官 480p 的 12 / 15 秒被拒 | 改用该档位明确允许的时长，或合法的 720p 配置 |
| 413 | 检查原文件及 Base64 后请求大小 |
| 409 | 保留原操作，核查幂等处理或请求冲突 |
| 429 | 降低频率，遵守重试提示，不并发创建相同任务 |
| 5xx / 网络超时 | 先核查是否已受理，不自动重提 |
| 内容审核 / 版权拒绝 | 查看明确错误，使用有权且符合要求的内容；模型名不保证通过 |
| 已完成但无法播放 | 下载原片，检查鉴权、文件完整性和编码，不重新生成 |
| 时长 / 像素与请求不一致 | 保留原片、任务 ID 和请求规格，联系站内客服 |

联系客服时提供任务 ID、模型、参数、北京时间、HTTP 状态码和脱敏错误。不要发送完整 Key、认证头或私人媒体签名链接。

## 14. 计费与失败处理

- 按条：档位单价 × 视频条数 × 账户适用倍率；一次 API 请求对应一条。
- 按秒：档位单价 × 成片秒数 × 账户适用倍率。
- 第 1 节已是本站售价，不另外叠加文档中的固定费用。
- 查询报价、查询已有任务与恢复下载不等于新建视频；不要通过重新 POST 解决下载问题。
- 画布提交前展示服务端报价，确认后预留余额，成功结算，明确失败按原任务处理退回。
- API 的账务结果以本站消费记录和实际处理状态为准。网络超时、待核查或前端暂停，不足以判断任务失败或退款完成。
- 若出现扣费与状态不一致，保留原任务并联系站内客服，不反复提交验证余额。
